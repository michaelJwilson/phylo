A generated plan has a stated shape: 2–5 steps, each saying how it will be
validated, ending with an **Open Questions** section that carries every
question on the desired behaviour. A reviewer now finds the questions in one
place instead of reading the prose for them, and a plan with none says so
rather than omitting the heading.

The shape is stated in `ROADMAP.md` §0.2, where the plan deliverable is
defined. Root `CLAUDE.md`'s Writing Style already governed every document,
docstring, comment, commit message and pull-request body; the list now names
plans and ticket comments too, which is what makes a plan subject to it
without the rule acquiring a second home.

`DEV.md` says which of the two it is: the mechanics — layout, checks, what the
templates hold — with the loop itself left to `ROADMAP.md` §0, named in the
opening line rather than left to be inferred from "project trajectory". Its
**Agentic Approach** rule references §0.2's staging sentence instead of
carrying its own copy, and a rule that was stated nowhere is stated: a pull
request implements a plan already approved.
