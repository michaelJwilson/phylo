A module's tests live beside it, under `python/phylo/<module>/tests/` —
regression tests and the benchmarks that pair with them, in one directory. This
reverses the layout rule that stood between issues #154 and #163: kind was the
outer axis, so a module's source, its tests and its coverage target were three
paths in two trees, and continuous integration had to map between them by hand.
One prefix now answers all three, which is what issue #161 needs to select
tests by what a pull request changed.

Tests belonging to no single module stay under `tests/`: `test_numerics.py`,
`test_claude_md_pointers.py`, the scaffolding hot-path test, the binding and
whole-package smoke tests, the shared helpers, and the fixtures.

Two consequences of putting tests inside the package, both handled rather than
discovered later. They are excluded from the wheel (`[tool.maturin] exclude`),
having previously been outside the packaged tree — a consumer installing
`phylo` has neither the fixtures nor pytest. And they are excluded from
coverage (`[tool.coverage.run] omit`), which otherwise measures the tests as
source: the statement count trebles and a release-gated test body that is
collected but never run reads as uncovered.

Benchmarks are deselected by filename (`--ignore-glob="*_bench.py"`) rather
than by directory, since they are no longer in one.

The test set is unchanged: the same 556 test functions collect before and
after, and 540 pass under `pytest -m "not release"`.
