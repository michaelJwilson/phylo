\begin{abstract}
\noindent
Phylogenetic inference is a discrete search whose every objective evaluation
contains a continuous optimization, and the two halves do not separate: a
better topology scored with badly fitted parameters looks worse than a poor
one scored well. This document reports machinery for that problem, built to
the standard that each claim is pinned against a source sharing no code with
what it checks. The optimization interface is model-agnostic by construction
--- an unconstrained parameter vector, a differentiable objective, and a map
back to named constrained parameters --- and fits a Potts chain, a hidden
Markov model, branch lengths and the general time-reversible model through
the same three methods. Discrete moves sit deliberately outside it: a move
changes what the parameter vector means, so it builds a new objective rather
than stepping within one, and the topology search that does so needed no
change to the optimizer. Felsenstein pruning agrees with brute-force
marginalization to $4.0 \times 10^{-14}$ relative across three backends;
fitted parameters are recovered inside intervals whose coverage is measured
against its nominal rate; hill climbing reaches the exhaustively enumerated
optimum, and the alignment size at which it recovers the generating topology
is measured against a stated bound. A reinforcement-learning estimator is
checked against an exact enumeration of its own gradient, and the cheap
reward a tree-searching agent would train on is validated against the
maximized one it replaces --- correlation $0.9568$ over all $105$ topologies
on six taxa, at $323$ times less cost. No comparison against established
inference software has been run, and no trained policy proposes moves yet;
Section~\ref{sec:planned} states what those claims would require.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Inferring a phylogeny is a mixed discrete--continuous optimization problem.
The discrete half is a search over tree topologies, whose count grows as
$(2n-5)!!$ and passes $10^{18}$ by twenty taxa. The continuous half is a fit,
per candidate, of that tree's branch lengths and substitution parameters ---
and the two do not separate, because a better topology scored with badly
fitted parameters looks worse than a poor one scored well. Every evaluation
of the discrete objective therefore contains a continuous optimization.

Classical heuristics propose topological moves by a fixed, hand-designed
rule: nearest-neighbour interchange, subtree prune-and-regraft, and their
compositions, applied greedily. The question this project asks is whether a
learned policy proposes better ones at a matched evaluation budget.

That question has a prerequisite the literature usually leaves implicit. A
learned proposal policy is only worth building on top of machinery whose
answers are known to be right, and "known to be right" has a specific
meaning here: pinned against a source that shares no code with the thing it
checks. This document reports that machinery and the checks that pin it.

\subsection{Contributions}
\label{sec:contributions}

\begin{enumerate}
  \item An optimization interface that is model-agnostic by construction ---
    an unconstrained parameter vector, a differentiable objective, and a map
    back to named constrained parameters --- demonstrated by fitting four
    instances through it unchanged: a Potts chain, a hidden Markov model,
    branch lengths on a tree, and the general time-reversible model
    (Section~\ref{sec:opt-interface}).
  \item The identification of discrete moves as an operation \emph{outside}
    that interface: a move changes what the parameter vector means, so it
    constructs a new objective rather than stepping within one
    (Section~\ref{sec:opt-interface}). Tree search is the first consumer of
    that seam, and needed no change to the optimizer.
  \item Felsenstein pruning in three backends, each pinned against
    brute-force marginalization to a relative deviation of
    $4.0 \times 10^{-14}$ (Figure~\ref{fig:backend-agreement}).
  \item Parameter recovery inside confidence intervals from the observed
    Fisher information, with the intervals' coverage measured against its
    nominal rate rather than assumed (Figures~\ref{fig:opt-recovery} and
    \ref{fig:opt-coverage}), and the estimability of the root branch pair
    established rather than asserted (Figure~\ref{fig:opt-branch-recovery}).
  \item The data requirement for topology recovery, measured against this
    project's own accuracy bound (Figure~\ref{fig:topology-accuracy}).
  \item A reinforcement-learning estimator checked against an exact
    trajectory-enumeration oracle, and a cheap phylogenetic reward validated
    against the expensive one it stands in for
    (Figure~\ref{fig:rl-reward-surface}).
\end{enumerate}

\section{Methods}
\label{sec:methods}

The machinery, in the order it composes: what the symbols mean, the

\subsection{Notation}

Two vocabularies are kept apart, because the machinery in this document is
deliberately indifferent to which application it serves. The first describes
an optimization problem; the second describes a phylogeny. Nothing in the
first refers to a tree.

\subsubsection{The optimization abstraction}
\label{sec:notation-abstraction}

An objective is a differentiable scalar $\objective(\params)$ over an
unconstrained vector $\params \in \mathbb{R}^d$, together with a map from
$\params$ to the constrained parameters a model is actually stated in ---
positive rates, distributions on a simplex. Minimization is the convention
throughout, so a likelihood-based objective is a negative log-likelihood.

A \emph{discrete move} changes the structure being fitted, and therefore
changes both the meaning and the dimension $d$ of $\params$. It is not a step
within an optimization; it constructs a new objective.

\subsubsection{The phylogenetic application}
\label{sec:notation-application}

Let $\states$ be the finite state space of a single character, with
$k = |\states|$; for nucleotide data $\states = \{A, C, G, T\}$ and $k = 4$.
The data $\data$ are an alignment of $n$ taxa over $m$ sites, so
$\data \in \states^{n \times m}$, with $\data_{\cdot s}$ the observed column
at site $s$.

A phylogeny is a pair $(\tree, \branch)$: a topology $\tree$ whose $n$ leaves
carry the taxa, and a vector $\branch$ of non-negative branch lengths,
measured in expected substitutions per site. Internal nodes represent
unobserved ancestors, and $\rootnode$ denotes the root.

\subsection{The likelihood}

Sites are modelled as independent given $(\tree, \branch, \Q, \bpi)$, so the
log-likelihood is a sum over columns,
%
\begin{equation}
  \log \mathcal{L}(\tree, \branch, \Q, \bpi \mid \data)
    = \sum_{s=1}^{m} \log \Pr(\data_{\cdot s} \mid \tree, \branch, \Q, \bpi).
  \label{eq:site-independence}
\end{equation}
%
The site term marginalizes over the unobserved states of every internal node.
Written directly, that is a sum over $k^{n-1}$ assignments --- intractable
beyond a handful of taxa. Felsenstein's pruning algorithm computes it in time
linear in $n$ by exploiting the tree's conditional independence structure
\citep{felsenstein2004}; it is the sum-product algorithm on a tree
\citep{mackay2003, koller2009}.

\subsubsection{Pruning}

Define the partial likelihood $L_u(i)$ as the probability of the data at the
leaves below node $u$, given that $u$ is in state $i$. At a leaf with
observed state $a$, $L_u(i) = \mathbb{1}[i = a]$. At an internal node $u$
with children $v$ joined by branches of length $t_v$,
%
\begin{equation}
  L_u(i) = \prod_{v \in \mathrm{children}(u)}
           \left( \sum_{j \in \states} P_{ij}(t_v) \, L_v(j) \right),
  \label{eq:pruning}
\end{equation}
%
and at the root $r$ the site likelihood is
%
\begin{equation}
  \Pr(\data_{\cdot s} \mid \cdot) = \sum_{i \in \states} \pi_i \, L_r(i).
  \label{eq:root}
\end{equation}

\begin{algorithm}[htbp]
\caption{Felsenstein pruning for one site}
\label{alg:pruning}
\begin{algorithmic}[1]
  \Require topology $\tree$, branch lengths $\branch$, rate matrix $\Q$,
           root distribution $\bpi$, observed column $\data_{\cdot s}$
  \Ensure site likelihood $\Pr(\data_{\cdot s} \mid \tree, \branch, \Q, \bpi)$
  \ForAll{nodes $u$ in post-order}
    \If{$u$ is a leaf with observed state $a$}
      \State $L_u(i) \gets \mathbb{1}[i = a]$ for all $i \in \states$
    \Else
      \State $L_u(i) \gets \prod_{v \in \mathrm{children}(u)}
             \sum_{j} P_{ij}(t_v) L_v(j)$ for all $i \in \states$
    \EndIf
  \EndFor
  \State \Return $\sum_{i} \pi_i L_r(i)$
\end{algorithmic}
\end{algorithm}

Algorithm~\ref{alg:pruning} costs $O(n k^2)$ per site against $O(k^{n-1})$
for direct marginalization. The two agree exactly, which makes brute-force
marginalization on small trees the reference implementation the pruning code
is tested against.

Partial likelihoods underflow for realistic $m$ and $n$, so the
implementation will rescale them per node and accumulate the log of the
scaling factors. Rescaling changes the arithmetic but not the result: the
rescaled and direct computations must agree to within floating-point
tolerance on small problems where both run.

\subsubsection{Differentiable backends}
\label{sec:backends}

Branch lengths $\branch$ are what gradient-based fitting and tree search
differentiate through, so an accelerated backend must keep them in the
autodiff graph rather than baking them into topology state. The PyTorch
backend (\texttt{pruning\_torch.py}, float64, CPU) takes $\branch$ as a
tensor separate from the topology and is accepted when its log-likelihood
agrees with the NumPy reference to $\mathrm{atol} = 10^{-9}$ -- the same
bound as the brute-force check above -- never relaxed to accommodate a
discrepancy. Gradients obtained from \texttt{torch.autograd} are checked
against central finite differences of the NumPy oracle (step
$\epsilon = 10^{-6}$) to $\mathrm{atol} = 10^{-6}$, the coarser bound set by
the finite-difference truncation and rounding error at that step size, not
by the autodiff computation itself.

\subsubsection{Rate variation across sites}
\label{sec:rate-variation}

Sites evolve at different rates. The standard treatment draws a
site-specific rate multiplier $r$ from a discretized gamma distribution with
mean one, and averages the site likelihood over the $c$ rate categories,
%
\begin{equation}
  \Pr(\data_{\cdot s} \mid \cdot)
    = \frac{1}{c} \sum_{g=1}^{c}
      \Pr(\data_{\cdot s} \mid \tree, r_g \branch, \Q, \bpi),
  \label{eq:gamma-rates}
\end{equation}
%
multiplying the cost of a likelihood evaluation by $c$
\citep{felsenstein2004}. \emph{Not yet implemented.}

\subsection{Simulation}

Simulation is how the implementation is tested: draw data from known
parameters, then check that each component recovers what the generating model
implies. Generation runs in pre-order, the reverse of pruning.

\begin{algorithm}[htbp]
\caption{Simulating an alignment under $(\tree, \branch, \Q, \bpi)$}
\label{alg:simulate}
\begin{algorithmic}[1]
  \Require topology $\tree$, branch lengths $\branch$, rate matrix $\Q$,
           root distribution $\bpi$, sites $m$, seeded generator
  \Ensure alignment $\data \in \states^{n \times m}$
  \For{$s \gets 1$ to $m$}
    \State draw the root state $x_r \sim \bpi$
    \ForAll{nodes $u$ in pre-order, $u \neq r$ with parent $p$ and branch $t_u$}
      \State draw $x_u \sim \Pmat(t_u)_{x_p, \cdot}$
    \EndFor
    \State record $x_u$ at every leaf $u$ as column $s$
  \EndFor
  \State \Return $\data$
\end{algorithmic}
\end{algorithm}

Every draw uses an explicitly seeded generator, so a simulated dataset is
reproducible from its seed. Topology, branch lengths, $k$, $\bpi$, seed and
site count are declared in a parameters file, and the generating truth is
retained alongside the alignment, so a dataset always carries what produced
it. Simulated substitution frequencies are checked against \eqref{eq:jc}
within a declared Monte Carlo tolerance.

Table~\ref{tab:sim-problem-sizes} in Section~\ref{sec:qa} lists every
simulation regression fixture at the problem sizes actually run, read
directly from each fixture's yaml; Figure~\ref{fig:sim-example} there shows
a complete generated instance at the smallest of them --- the Newick string
and the leading simulated sites of the alignment.

\subsection{Tree search}
\label{sec:search}

\subsubsection{The size of the problem}

The number of distinct unrooted binary topologies on $n$ taxa is the double
factorial $(2n - 5)!!$ \citep{rosen2019}, which grows faster than exponentially
(Table~\ref{tab:treecount}). Exhaustive search is impossible past a handful
of taxa, and finding the optimal tree under either the parsimony or the
likelihood criterion is NP-hard \citep{felsenstein2004}. Practical inference
is therefore heuristic: start somewhere, propose rearrangements, keep what
scores better.

\subsubsection{Move sets}

Two rearrangement neighbourhoods define the search graph
\citep{felsenstein2004}: NNI and SPR, defined in
Appendix~\ref{app:background}. NNI's neighbourhood is small, cheap, and
local; SPR's is quadratic in $n$, so each step costs more, but its larger
reach escapes local optima that trap NNI.

Since neighbouring topologies differ only near the affected edges, most
partial likelihoods are unchanged between a tree and its neighbour. Caching
and recomputing only the invalidated path is what makes tree search
affordable, and is a design requirement on the likelihood engine rather than
an optimization to add later.

\subsubsection{Canonical serialization}
\label{sec:canonical}

Newick notation is not a unique encoding: one topology admits many strings,
differing by the order in which children are written and by where the
string is rooted. A search that keys on the raw string therefore fails to
recognize a tree it has already scored, and a model trained on raw strings
learns to distinguish spellings that carry no phylogenetic meaning.
Algorithm~\ref{alg:canonical} removes both problems by fixing a
representative.

\begin{algorithm}[htbp]
\caption{Canonical form of an unrooted binary tree with labelled leaves}
\label{alg:canonical}
\begin{algorithmic}[1]
  \Require tree $\tree$ with leaves labelled from a totally ordered set
  \Ensure a string identifying $\tree$'s topology uniquely
  \State root $\tree$ at the leaf whose label is smallest in that order
  \ForAll{nodes $u$ in post-order}
    \If{$u$ is a leaf}
      \State $\kappa(u) \gets \text{label}(u)$
    \Else
      \State sort the children $v$ of $u$ by $\kappa(v)$
      \State $\kappa(u) \gets$ the concatenation of $\kappa(v)$ in that order
    \EndIf
  \EndFor
  \State \Return $\kappa(\text{root})$, emitting children in sorted order
\end{algorithmic}
\end{algorithm}

Rooting at the smallest label is well defined for any labelled tree, and the
child order is fixed bottom-up by keys that depend only on the subtree
below, so the output depends on the topology alone. Hashing the keys keeps
the cost at $O(n \log n)$ \citep{clrs2022}. Branch lengths are carried
separately, as a vector in canonical node order, so one topology under two
length assignments shares a key --- which is what makes the key usable for
memoizing likelihood evaluations across a search.

Both required properties are tested rather than assumed: two trees produce
the same string exactly when they are the same topology, checked by randomly
re-rooting and permuting the children of one tree and against distinct trees;
and parsing a canonical string reproduces the tree that produced it.

\subsubsection{Extensions to the move set}
\label{sec:extensions}

Three extensions target the same bottleneck: the number of likelihood
evaluations a search spends. All three are proposals. \emph{Not yet
implemented.}

\paragraph{Bounding whole sets of trees.} Scoring every neighbour exactly
wastes work when most are poor. A cheap \emph{upper} bound on the likelihood
attainable anywhere in a set of topologies discards the whole set once it
falls below the best log-likelihood already achieved, in the manner of branch
and bound \citep{clrs2022}. Two sources are worth trying: relaxations of the
pruning recursion \eqref{eq:pruning} that replace the product over children
by something cheaper and provably no smaller; and compressed summaries of the
alignment, where identical site patterns already collapse and coarser
encodings trade tightness for speed \citep{blahut2003}. Soundness is the
whole game --- a bound that can fall below an attainable likelihood silently
discards the optimum --- so each candidate needs a proof, and a test that
searches small trees exhaustively for a counterexample.

\paragraph{Multi-moves.} Composing several NNI or SPR rearrangements into
one action reaches topologies no single move reaches, at the cost of a much
larger action space; in reinforcement-learning terms these are temporally
extended actions \citep{suttonbarto2018}. Rather than fixing how many
rearrangements a compound move contains, draw the composition during
training from a Dirichlet process, so the number of distinct compound moves
grows with the evidence for them \citep{mackay2003}. The measure of success
is unchanged: fewer likelihood evaluations for the same likelihood reached.

\paragraph{A transformer policy over Newick strings.} A topology serializes
to a Newick string, which a transformer can consume directly --- tokenize
the string, pretrain on simulated trees, then fine-tune the policy with the
usual policy-gradient machinery
\citep{raschka2024, lapan2020, suttonbarto2018}. The input is the canonical
form of Section~\ref{sec:canonical}, which settles the encoding question:
one topology, one string. An architecture invariant to child order and root
placement buys the same property at greater cost, and without supplying the
memoization key the search needs anyway. Compression applies on top,
replacing recurring subtrees by dictionary symbols --- an extended alphabet
over the canonical string \citep{blahut2003} --- shortening the sequence the
transformer attends over.

\subsubsection{Hill climbing}
\label{sec:hill-climbing}

The simplest search that uses the move sets above: score the current
topology, score every neighbour, move to the best strict improvement, stop
when none improves. It is the baseline the learned policy of
Section~\ref{sec:rl} has to beat, so it is worth stating precisely rather
than assuming.

Two details are not incidental. A candidate is scored by \emph{fitting} it
--- the continuous parameters are re-estimated for every topology, because a
topology's likelihood is its maximized likelihood and comparing trees at
shared branch lengths compares nothing. And the budget is counted in
candidate fits rather than in time: fitting dominates by four orders of
magnitude over generating the neighbourhood, and a wall-clock budget would
make a result depend on the machine that produced it.

The discrete move is what connects this section to
Section~\ref{sec:opt-interface}. A move changes the structure being fitted,
so it changes what the parameter vector means and how long it is; it cannot
be a step inside a fit over a fixed-length vector. It builds a new objective,
and this loop is what owns that construction. The optimizer needed no
knowledge of trees to serve it.

\subsubsection{Parsimony and likelihood}

The \emph{large parsimony} problem asks for the topology minimizing the
number of state changes needed to explain the data. We keep the search
problem and replace the criterion: candidates are scored by the maximized
log-likelihood of \eqref{eq:site-independence}, with the continuous
parameters $(\branch, \Q, \bpi)$ fitted per topology. Likelihood is the more
principled criterion --- it models the substitution process rather than
counting changes, and it is statistically consistent where parsimony can be
positively misleading \citep{felsenstein2004} --- at the cost of a far more
expensive score.

\subsection{Gradients}

Fitting $(\branch, \Q, \bpi)$ for a candidate topology is a continuous
optimization, and gradients make it tractable. Differentiating
\eqref{eq:transition} with respect to a branch length gives
%
\begin{equation}
  \frac{\partial \Pmat(t)}{\partial t} = \Q \exp(\Q t) = \Q \, \Pmat(t).
  \label{eq:dpdt}
\end{equation}
%
For a reversible $\Q$ with eigendecomposition $\Q = \mathbf{U} \Lambda
\mathbf{U}^{-1}$, both the exponential and its derivative are diagonal in the
eigenbasis,
%
\begin{equation}
  \Pmat(t) = \mathbf{U} e^{\Lambda t} \mathbf{U}^{-1}, \qquad
  \frac{\partial \Pmat(t)}{\partial t}
    = \mathbf{U} \Lambda e^{\Lambda t} \mathbf{U}^{-1},
  \label{eq:eigen}
\end{equation}
%
so a single decomposition serves every branch. Gradients of the
log-likelihood with respect to all branch lengths follow from reverse-mode
automatic differentiation through the pruning recursion
\eqref{eq:pruning}, at a cost proportional to one forward evaluation
\citep{goodfellow2016, prince2023}. The optimizer consuming them is a
standard constrained quasi-Newton or trust-region method
\citep{nocedal2006}; the parameters carry constraints --- non-negative
branch lengths, a normalized $\bpi$ --- so the geometry of the statistical
manifold, and the natural gradient it induces, is the principled setting
\citep{amari2016}.

Analytic and automatic gradients are checked against central finite
differences,
%
\begin{equation}
  \frac{\partial f}{\partial \theta}
    \approx \frac{f(\theta + h) - f(\theta - h)}{2h},
  \label{eq:finite-difference}
\end{equation}
%
with $h$ chosen to balance truncation against round-off. This check is a
required test for any differentiable component, and is implemented for every
objective the optimizer accepts.

\subsubsection{The optimization interface}
\label{sec:opt-interface}

The optimizer is deliberately ignorant of what it optimizes. It takes an
unconstrained parameter vector, a differentiable scalar to minimize, and a
map back to the named constrained parameters; nothing in it refers to a
tree, and a test asserts that the module imports nothing from the simulation,
likelihood or search packages. Constraints are imposed by construction rather
than by projection --- a positive scale through a log map, a distribution
through a softmax --- so no step can leave the feasible set.

That map must also be injective. A softmax over $n$ logits is invariant to
adding a constant to all of them, so one direction of the parameter space is
exactly flat; pinning the first logit removes it and makes the map a bijection
onto the simplex. The same gauge appears in the Potts field of
Section~\ref{sec:qa} and is fixed the same way.

Discrete moves sit outside this interface. A move changes the structure ---
a different topology, chain length or state count --- and so changes what the
parameter vector means and how long it is. It therefore constructs a
\emph{new} objective rather than stepping inside a fit over a fixed-length
vector, and the loop that proposes moves owns that construction. This is what
lets the tree search of Section~\ref{sec:search} and the continuous fit share
an optimizer without either knowing about the other.

Fitted parameters are reported with intervals from the observed Fisher
information --- the Hessian of the negative log-likelihood at the optimum ---
pushed through the constraint map by the delta method. A flat direction leaves
that information singular and the interval undefined rather than merely wide,
so reporting is gated on the ratio of its smallest to its largest eigenvalue;
rounding leaves an exactly flat direction tiny, not zero. The gate is not
hypothetical here: the two branches below a rooted binary tree's root realize
a ratio of $6.7 \times 10^{-8}$, against $6.1 \times 10^{-2}$ for the same
tree with that pair fitted as their sum. The intervals are asymptotic, and
Section~\ref{sec:qa} reports how fast they reach their nominal coverage and
shows the root invariance directly.

\subsection{Reinforcement-learning formulation}
\label{sec:rl}

Classical heuristics propose moves by a fixed, hand-designed rule. We ask
whether a learned policy proposes better ones, and cast the search as a
Markov decision process $(\mathcal{S}, \mathcal{A}, P, R, \gamma)$
\citep{suttonbarto2018}:

\begin{description}
  \item[State.] The current topology with its fitted continuous parameters,
    together with a summary of the alignment.
  \item[Action.] A move drawn from the NNI or SPR neighbourhood of the
    current topology.
  \item[Transition.] Applying the move and refitting the continuous
    parameters --- deterministic given the action, up to the optimizer.
  \item[Reward.] The improvement in maximized log-likelihood,
    $R = \log \mathcal{L}(\tree') - \log \mathcal{L}(\tree)$.
  \item[Episode.] One search trajectory from a starting tree, terminating on
    a step budget or when no move improves the score.
\end{description}

The natural performance measure is not the likelihood reached but the
likelihood reached \emph{per likelihood evaluation}: every method converges
given unbounded evaluations, so the comparison against a hill-climbing
baseline has to be made at equal budget.

\subsubsection{Why this reward, and what it implies}
\label{sec:rl-reward}

The reward is a difference of log-likelihoods, which is not an arbitrary
choice: it makes the undiscounted return telescope. Over a trajectory
$\tree_0, \dots, \tree_T$,
%
\begin{equation}
  \sum_{t=0}^{T-1} R_t
    = \sum_{t=0}^{T-1} \bigl[ \log \objective(\tree_{t+1})
        - \log \objective(\tree_t) \bigr]
    = \log \objective(\tree_T) - \log \objective(\tree_0),
  \label{eq:telescope}
\end{equation}
%
so the return of an episode is exactly the total improvement it achieved,
independent of the path taken to it. A policy maximizing expected return is
therefore maximizing the quantity the benchmark measures, with no reward
shaping to justify separately.

This forces $\gamma = 1$. Any $\gamma < 1$ breaks the telescoping and
prefers improvement found early over the same improvement found late ---
defensible when a trajectory may not terminate, but here episodes are capped
by an evaluation budget, so the return is a finite sum and needs no
discounting to converge.

\subsubsection{Policy gradient and its baseline}
\label{sec:rl-gradient}

The action set is the move neighbourhood, whose size varies with $n$ and with
the move type, so the policy scores candidate moves rather than indexing a
fixed action space: $\pi_{\params}(a \mid s) \propto \exp f_{\params}(s, a)$ over
the available $a$. The gradient of expected return is the standard score-function
estimator \citep{suttonbarto2018},
%
\begin{equation}
  \nabla_{\params} J(\params)
    = \mathbb{E}_{\pi_{\params}} \Bigl[
        \sum_{t=0}^{T-1} \nabla_{\params} \log \pi_{\params}(a_t \mid s_t)
        \bigl( G_t - b(s_t) \bigr) \Bigr],
  \qquad
  G_t = \sum_{u=t}^{T-1} R_u,
  \label{eq:policy-gradient}
\end{equation}
%
with $b(s_t)$ a baseline that leaves the estimator unbiased --- it multiplies
a term of zero expectation --- while reducing its variance. The variance
matters more here than the bias-free property: $G_t$ is a sum of
log-likelihood differences whose scale depends on the alignment, so without a
baseline the gradient magnitude varies by orders of magnitude between
problems. A learned state-value estimate $\hat{v}(s_t)$ is the usual choice
and is the one that makes $G_t - b(s_t)$ an advantage.

\subsubsection{Credit assignment}
\label{sec:rl-credit}

Tree search makes the credit-assignment problem sharp. A move that unlocks a
region of the space may itself lower the likelihood, with the gain arriving
several moves later; by \eqref{eq:telescope} the return correctly attributes
that gain to the whole trajectory, but the per-step estimator in
\eqref{eq:policy-gradient} must still spread it over the actions that earned
it. Two consequences for an implementation. Episodes cannot be truncated
arbitrarily, since a truncation that lands between the sacrifice and the
payoff teaches the opposite of the truth. And a greedy baseline --- hill
climbing --- is exactly a policy that refuses every negative $R_t$, so
beating it requires the agent to accept some, which is the behaviour the
variance-reduced estimator has to be able to learn rather than average away
\citep{suttonbarto2018, lapan2020}.

\subsubsection{Status: the estimator, on a landscape that is not a tree}
\label{sec:rl-status}

The machinery above is implemented and the phylogenetic environment is not.
That split is deliberate. An interface justified by one application is shaped
by it, so the estimator is developed against a reference environment chosen
for having nothing to do with trees: single-site flips over the same 1-D
Potts chain that Section~\ref{sec:qa} fits continuously. One model, appearing
once as an objective and once as a search problem, is what makes the shared
abstraction a demonstration rather than a claim.

Two properties of that landscape make it a usable testbed. Its reward
decomposes exactly into the two features the policy scores, so hill climbing
is the weight vector proportional to $(J, 1)$ --- the baseline sits
\emph{inside} the policy class, and beating it is a statement about learning
rather than about two unrelated algorithms. And it is small enough to
enumerate: every configuration can be scored, so ``found the best one'' is
checkable, exactly as Section~\ref{sec:hill-climbing} enumerates topologies
below eight taxa.

Enumeration also supplies the oracle the estimator itself is checked against.
With a finite action set and a finite horizon the trajectory set is finite,
so $J(\params)$ is a closed form and $\nabla J$ follows by differentiating it;
the sampled estimator is then an unbiasedness claim to be checked rather than
cited. Measured on that oracle: the enumerated gradient agrees with central
finite differences to $1.5 \times 10^{-11}$ relative, and the sampled
estimator with the enumerated gradient to $9.9 \times 10^{-3}$ over
$6000$ episodes. A myopic variant --- crediting each action with its own
reward instead of everything that followed --- is off by $71\%$, which is the
margin that makes the check worth running.

On that landscape a learned policy beats hill climbing at a matched decision
budget, reaching the enumerated optimum from $86.6\%$ of the $81$ starting
configurations against greedy's $80.2\%$, in $8$ of $8$ training seeds. The
mechanism is the one Section~\ref{sec:rl-credit} predicts: the episode ends at
a local maximum, so a policy that occasionally accepts a negative $R_t$ can
route around a barrier a greedy searcher walks into. This is a harder problem
than the tree fixture of Section~\ref{sec:hill-climbing}, where the optimum
led the runner-up by $41.6$ log units and hill climbing was never challenged.

\subsubsection{The phylogenetic environment, and the reward it can afford}
\label{sec:rl-phylo}

The application instance is now built: a state is a topology, an action is a
neighbour under NNI or SPR, and the reward is the improvement in
log-likelihood. It lives in the search package rather than beside the
estimator, for the reason the phylogenetic objective lives beside the
likelihood --- an agent developed against a tree is an agent shaped by trees,
and the module that must stay model-agnostic may import no application code.

The reward is where the cost is. Scoring a candidate at its \emph{maximized}
branch lengths is the honest quantity and runs an optimization per candidate;
an episode evaluates a whole neighbourhood at every step, so training on it
is not affordable. Scoring at fixed known parameters instead is the
substitution Figure~\ref{fig:rl-reward-surface} measures.

One detail of that substitution is forced rather than chosen. ``The known
parameters'' do not survive a change of topology: a branch length belongs to
an edge, and a different topology has different edges. The only thing that
transfers is a scalar, so every candidate is scored at one fixed branch
length --- which makes the cheap reward a \emph{different surface} from the
fitted one rather than an approximation of it, and is why the two are
compared rather than assumed interchangeable. This is the same fact
Section~\ref{sec:opt-interface} states about discrete moves, seen from the
other side: a move changes what the parameter vector means.

Measuring that comparison turned up something about the fitted surface worth
recording on its own. It does not totally order topologies: many candidates
share a maximized log-likelihood to within the optimizer's own convergence,
because the branch that would distinguish them is fitted to zero and the tree
collapses to the same polytomy --- the effect
Section~\ref{sec:hill-climbing}'s rejected topology shows one instance of.
Their relative order is therefore not a property of the model, and a rank
correlation, which depends on it, is not a measurement: perturbing the fitted
scores by one part in $10^{9}$ moves Spearman's $\rho$ by up to $0.04$. The
comparison is reported as a linear correlation, which moves by the size of
the perturbation instead. The cheap surface has no such degeneracy, since
fixing the branch lengths at a positive value is exactly what forbids the
collapse.

\emph{Not claimed here:} that a learned policy beats hill climbing on trees.
The 6-taxon fixture cannot support that claim in either direction --- greedy
already reaches the enumerated optimum from every start, as
Section~\ref{sec:hill-climbing} reports, so there is nothing left to win. A
fixture that separates them is a harder problem than exhaustive enumeration
can referee, and that is the obstacle between here and Milestone~8 rather
than any missing machinery.

\emph{Not yet implemented:} PPO and a learned state-value baseline.

\subsection{Computational structure}

Likelihood evaluation dominates the run time: every proposed move costs at
least one evaluation, and search proposes many. Its structure is favourable
--- sites are independent by \eqref{eq:site-independence}, and the per-node
work in \eqref{eq:pruning} is a small dense matrix--vector product --- so the
computation is a batched, data-parallel reduction over a tree.

The project's performance rule follows from that. Where a kernel plausibly
achieves an order of magnitude over the vectorized NumPy reference at the
sizes actually run, it targets the GPU through PyTorch, Triton, or JAX, which
supply autodiff and batching alongside the parallelism; otherwise the work
goes to the Rust backend. The threshold is a measured benchmark, not an
expectation, and every accelerated kernel keeps its reference implementation
as a pinned oracle. Kernel-level considerations --- memory hierarchy,
occupancy, parallel reduction --- follow \citet{pmpp2022}; the CPU-side
counterparts, caching and where time actually goes, follow
\citet{bryant2015}, and the backend itself is Rust \citep{blandy2021}.

Memory is the constraint to watch: partial likelihoods occupy
$O(n \, m \, k \, c)$ floating-point values for $n$ taxa, $m$ sites, $k$
states, and $c$ rate categories, before any caching of unchanged subtrees
across proposals.

\section{Discussion}
\label{sec:discussion}

Two results are worth separating from the rest, because they were not what
was expected.

The first is that the abstraction held. An optimization interface written
without reference to any model was expected to need widening once a real
application arrived; it did not. Branch lengths, exchangeabilities and
stationary frequencies fit through the same three methods that fit a Potts
chain, and the topology search that consumes them required no change to the
optimizer at all. The seam that made that work is the one in
Section~\ref{sec:opt-interface}: a discrete move changes what the parameter
vector means, so it builds a new objective instead of stepping inside one.
Stating that as an exclusion, rather than absorbing moves into the optimizer,
is what kept the interface model-agnostic.

The second is that the fitted likelihood does not totally order topologies.
Fitting each of the 105 unrooted topologies on six taxa produces only 52
distinct maxima: where the branch that would distinguish two trees is fitted
to zero, both collapse to the same polytomy and share a likelihood exactly.
This is a property of the objective, not of the optimizer, and it has a
practical consequence --- any statistic over topology rankings is
discontinuous in the fitted values, so a rank correlation computed on them is
not reproducible across machines. Section~\ref{sec:res-reward} reports a
linear correlation for that reason.

\subsection{Threats to validity}
\label{sec:threats}

The exhaustive enumeration that makes ``found the best tree'' checkable also
bounds where it can be checked: $(2n-5)!!$ passes ten thousand at eight
taxa. Every search result here is therefore established at a size where
hill climbing is not challenged --- on the six-taxon fixture the optimum
leads the runner-up by $41.6$ log units and greedy reaches it from every
start. That the searches succeed is evidence the machinery is correct, and no
evidence at all about the hard instances the project exists to attack.

The simulated data is generated by the same models the likelihood assumes, so
model misspecification is untested by construction. Real alignments violate
those assumptions, and Milestone~9 is where that is confronted.

\subsection{Planned work}
\label{sec:planned}

The claims this document cannot yet make, and the figures that would make
them:

\begin{description}
  \item[Competitiveness.] Maximized log-likelihood against evaluation budget,
    for the learned policy, hill climbing, IQ-TREE~2 and RAxML-NG on shared
    seeds. Requires those packages in the environment and the benchmark
    harness of Milestone~7. Until it exists, no statement in this document
    compares the method to established software.
  \item[A trained phylogenetic agent.] The learning curve of a policy over
    tree moves. The obstacle is a fixture rather than machinery: separating a
    policy from greedy needs a problem harder than exhaustive enumeration can
    referee, so the oracle that validates the search cannot validate the
    agent that replaces it.
  \item[Scale.] Runtime and memory against $n$ and $L$ across the range
    \texttt{ROADMAP.md} specifies. Memory is deterministic and can be
    reported here; runtime cannot, since a figure in this document is
    regenerated by continuous integration on hardware that varies, and a
    timing committed into it would neither reproduce nor mean anything. Those
    numbers live in the benchmark suite.
  \item[Rate variation across sites, and GPU dispatch.] Both are specified in
    Section~\ref{sec:rate-variation} and Section~\ref{sec:backends} and
    neither is built.
\end{description}

\section{Conclusions}
\label{sec:conclusions}

A model-agnostic optimization interface serves four instances unchanged, and
excluding discrete moves from it is what makes that possible rather than a
limitation of it. Felsenstein pruning agrees with brute-force marginalization
to $4.0 \times 10^{-14}$ relative across three backends. Parameters are
recovered inside intervals whose coverage is measured rather than assumed.
Hill climbing reaches the exhaustively enumerated optimum, and the alignment
size at which it does so is measured against this project's own accuracy
bound. A reinforcement-learning estimator is checked against an exact
enumeration of its own gradient, and the cheap reward a phylogenetic agent
would train on is validated against the expensive one it replaces.

What remains is the part the project is named for: a policy that proposes
better moves than the hand-designed rule, demonstrated against established
software on problems large enough for the comparison to matter. The
machinery for it is built and pinned. The evidence is not.

\subsection{NNI and SPR}
\label{app:nni-spr}

Two rearrangement neighbourhoods define the tree-search graph used in
Section~\ref{sec:extensions} and throughout \citep{felsenstein2004}:

\begin{description}
  \item[NNI (nearest-neighbour interchange).] Each internal edge of an
    unrooted binary tree separates four subtrees, which can be rejoined in
    three ways; two are new topologies. With $n - 3$ internal edges, the NNI
    neighbourhood contains $2(n-3)$ topologies --- small, cheap, and local.
  \item[SPR (subtree prune and regraft).] Detach a subtree and reattach it at
    another edge. The neighbourhood is quadratic in $n$, so each step costs
    more, but the larger reach escapes local optima that trap NNI.
\end{description}

\section{The substitution model}
\label{app:substitution}

Character evolution along a branch is a continuous-time Markov chain on
$\states$ with rate matrix $\Q$, whose off-diagonal entries $q_{ij} \ge 0$
give the instantaneous rate of substitution from state $i$ to state $j$ and
whose rows sum to zero,
%
\begin{equation}
  q_{ii} = -\sum_{j \neq i} q_{ij}.
  \label{eq:generator}
\end{equation}
%
Transition probabilities over a branch of length $t$ follow from the matrix
exponential,
%
\begin{equation}
  \Pmat(t) = \exp(\Q t), \qquad
  P_{ij}(t) = \Pr(X_t = j \mid X_0 = i).
  \label{eq:transition}
\end{equation}
%
$\Pmat(t)$ is a stochastic matrix: $P_{ij}(t) \ge 0$ and each row sums to
one. Both properties are invariants the implementation is tested against.

\subsection{Reversibility and the root distribution}
\label{sec:reversibility}

The models used here are time-reversible with respect to a distribution
$\bpi$, meaning they satisfy detailed balance,
%
\begin{equation}
  \pi_i q_{ij} = \pi_j q_{ji} \quad \text{for all } i, j.
  \label{eq:detailed-balance}
\end{equation}
%
Reversibility has two consequences we rely on. First, $\bpi$ is the
stationary distribution of the chain, which makes it the natural choice for
the distribution of states at the root. Second, the likelihood is invariant
to where the root is placed on the tree --- Felsenstein's \emph{pulley
principle} \citep{felsenstein2004} --- so an unrooted topology suffices for
inference, and re-rooting is a test the implementation must pass rather than
a modelling decision.

Every reversible rate matrix factorizes in the same way, which is the general
time-reversible (GTR) model of Section~\ref{sec:gtr}, eq.~\eqref{eq:gtr}; the
familiar JC69, K80 and HKY85 models are constrained special cases
\citep{felsenstein2004}. Branch lengths measure expected substitutions per
site, which fixes the scale of $\Q$ through the normalization
%
\begin{equation}
  -\sum_{i} \pi_i q_{ii} = 1 .
  \label{eq:normalisation}
\end{equation}
%
Without \eqref{eq:normalisation}, $\Q$ and $\branch$ trade off against each
other and neither is identifiable.

\subsection{The general time-reversible model}
\label{sec:gtr}

Jukes--Cantor has no free rate parameters, so there is nothing in $\Q$ or
$\bpi$ to estimate under it. The general reversible model supplies some:
%
\begin{equation}
  \Q_{ij} = s_{ij} \, \pi_j \quad (i \neq j), \qquad
  \Q_{ii} = -\sum_{j \neq i} \Q_{ij},
  \label{eq:gtr}
\end{equation}
%
with $s$ symmetric --- the \emph{exchangeabilities} --- and $\bpi$ the
stationary distribution. Detailed balance, $\pi_i \Q_{ij} = \pi_j \Q_{ji}$,
follows immediately from the symmetry of $s$, so \eqref{eq:gtr} is reversible
by construction rather than by assumption, and the eigendecomposition
\eqref{eq:eigen} applies exactly.

Two normalizations are gauges rather than conventions, and a third appears
once $\bpi$ is fitted. Each removes a direction along which the likelihood is
exactly flat; a flat direction makes the observed information singular, so
without them no parameter of the model has a confidence interval at all.
First, $\Q$ and $c\Q$ describe the same process at branch lengths $t$ and
$t/c$, so $\Q$ is scaled to one expected substitution per unit time,
$-\sum_i \pi_i \Q_{ii} = 1$; this is what makes a branch length mean
``expected substitutions per site''. Second, the same freedom reappears in
$s$, since scaling every entry is undone by that normalization, so one entry
is held at $1$. Third, $\bpi$ is optimized through a softmax whose first
logit is pinned, since adding a constant to all of them changes nothing.

Setting every $s_{ij}$ equal and $\bpi$ uniform must reproduce the
Jukes--Cantor rate matrix exactly, which is how the implementation is
validated --- against a model this document has already pinned against its
own closed form, rather than against a restatement of \eqref{eq:gtr}.

\subsection{The \texorpdfstring{$k$}{k}-state Jukes--Cantor model}
\label{sec:jc}

The most constrained case is worth stating in closed form, because it gives
the simulator an oracle that owes nothing to our likelihood code. Take all
exchange rates equal and $\bpi$ uniform on $k$ states. Under the
normalization \eqref{eq:normalisation}, the transition probabilities over a
branch of length $t$ are
%
\begin{equation}
  P_{ii}(t) = \frac{1}{k} + \frac{k-1}{k}\, e^{-kt/(k-1)}, \qquad
  P_{ij}(t) = \frac{1}{k} - \frac{1}{k}\, e^{-kt/(k-1)} \quad (i \neq j).
  \label{eq:jc}
\end{equation}
%
At $t = 0$ this gives the identity, and as $t \to \infty$ every entry tends
to $1/k$, the stationary distribution. For $k = 4$ it is JC69
\citep{felsenstein2004}. Simulated substitution frequencies are checked
against \eqref{eq:jc} within Monte Carlo error, which tests the simulator
independently of the pruning implementation --- if both were validated
against each other, a shared error would pass unnoticed.
